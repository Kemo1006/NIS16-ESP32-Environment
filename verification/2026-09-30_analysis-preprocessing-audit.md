# Verification: are the analysis outputs actually preprocessed properly and current with the raw exports?

**Date:** sep. 30, 2026
**Verdict:** ✅ **CONFIRMED** — the preprocessing itself is sound on all 6 analysis outputs. Two
*data* gaps found (not preprocessing faults), one of which should be cleaned up.

## The claim

User: *"do the analysis and data showed already preprocessed? make sure that the data are
preprocessed properly."*

Split into checkable sub-claims:

1. Every raw run under `datasets/exports/` has a corresponding analysis output.
2. No analysis output is **stale** — each is newer than the exports it derives from.
3. No **repeat contamination** — a cell holding r1–r4 side by side did not pool them into one table.
4. The outputs are **schema-consistent** with each other.
5. The outputs are **reproducible** under the current (uncommitted-modified) analysis code.
6. The raw exports pass the project's own **integrity** checks.
7. No **pre-baseline contamination** (the thing `verify_attack.py` blames when it excludes a feature).

## What this means (plain language)

The preprocessing is fine. Nothing needs re-running. Each of the four runs in the busy
`blackhole/linear/home/highload` folder was processed separately and cleanly, none of the outputs
is out of date, and the oldest table — the one most at risk, because it was built before the last
code edit — regenerates **bit-for-bit identical** under today's code.

Two things are worth acting on, and neither is a preprocessing bug:

- **Two mis-filed files sit in a `G402` folder but were actually recorded at `home`.** They are exact
  duplicates of files already archived, so nothing is lost by deleting them — but if anyone ever runs
  the pipeline on that folder, the location is read **from the folder path**, so home data would be
  labelled as G402 data.
- **The no-attack (baseline) run has no sniffer capture**, so its MAC-retry column is 100 % empty.
  That means the attack-vs-no-attack MAC retry comparison cannot be made from current data.

## Conflicts between sources

**The `G402` cell contradicts its own contents.** `preprocess.py` derives a run's
`attack/topology/location/scenario` from its **folder path** (`_run_context_from_path`). The two files
under `exports/blackhole/linear/G402/highload/` would therefore be labelled `location = G402`. They are
not G402 data:

```
fe36903d…  G402/highload/child_node5_…_r3_sept28_0115AM_telem.csv
fe36903d…  home/highload/trimmed/_archive/child_node5_…_r3_sept28_0115AM_telem.csv
5c4da471…  G402/highload/child_node6_…_r3_sept28_0105AM_telem.csv
5c4da471…  home/highload/trimmed/_archive/child_node6_…_r3_sept28_0105AM_telem.csv
```

Byte-identical (md5) to files archived under **home**. They belong to the superseded sep. 28 r3 attempt,
whose full set (root + arrivals + 5 children) lives in `home/highload/trimmed/_archive/`.

**Which source wins:** the archived home copies. The G402 pair is a stray duplicate, safe to delete —
the data survives in `_archive/` either way. This is the same failure mode as the sep. 18 dataset audit
(`thesis_dataset_audit`: "G402 folders mixed 6 runs under r1"), so the folder has a history of this.
