### ✅ M5 integrity validator — finished & de-bugged
`tools/validate_integrity.py` now performs the full check set the milestone asks for:
**schema-width (corruption) · per-phase coverage · timestamp monotonicity · `gt_label`
label integrity · SHA-256 manifest.** Two real defects were found and fixed while wiring it up:

| 🐛 | Bug | Impact | Fix |
|---|---|---|---|
| **1** | Filename parser only accepted `root\|victim`, but the exporter defaults to `--role child` | **Every `child_*.csv` silently skipped its coverage & role checks** — the "validator" was bypassing most real files | Parser now accepts `child`; coverage runs on those files |
| **2** | No `gt_label` validation existed at all | The ground-truth column M8 separates on was never checked | Added label check: `gt_label` must match the Table 4.1 phase→label map (baseline/cooldown→0, blackhole→1, wormhole→2) |

> 🔎 **Immediately paid off:** with `child_*` files finally being parsed, the validator caught
> genuine **phase-bleed in the control-victim captures** (wormhole-phase rows in files tagged
> `attack=none`) that had been going unreported.

### 🚨 New data-quality finding — 16 files FAIL on timestamp regression
Now that the validator runs on everything, a full pass over `tools/exports/` reports:

```
55 files — 7 PASS, 32 WARN, 16 FAIL
```
The **16 FAILs are all timestamp regressions**: data from an earlier, un-wiped run bleeding into
a later capture (e.g. `timestamp_us` jumping backwards mid-file). These are **corrupted runs, not
a validator bug** — they must be **re-captured** (wipe SPIFFS between runs), not patched.
The WARNs are mostly the known linear-mesh instability (truncated/duplicated phases).

## ❓ Q&A — The Null-Value Question (still current)

> **Your question:** *"Is it normal to have null values in some columns/rows in the EDA tables?"*

### ✅ Short answer: **Yes — NaN cells are normal, expected, and documented. Not a bug.**
NaN cells fall into three legitimate buckets — **role-specific** (a forwarding ratio is undefined
for a node that doesn't relay; PDR undefined for the root), **attack-specific** (`Tunnel*` exist
only in wormhole runs), and **firmware-blocked** (`LatencyHopRatio` / `TunnelLatency` — no RTT leg
exists). `features.py` correctly keeps `PDR = 0.0` (real blackhole signature) distinct from
`PDR = NaN` (root never heard the node). Nothing to fix here — this is by design.
