# Runbook: WORMHOLE attack run - v2026-09-14

> Two attacker boards (**Node A** near root, **Node B** near victims) joined by a **wired UART
> cable** (the out-of-band "tunnel"). During the attack, Node B forwards each probe to root
> normally AND tunnels a copy to Node A, which re-injects it - so the root receives the **same
> probe twice** (duplicate + latency mismatch). Ground-truth: `0 -> 2 -> 0`.
> Hub: `docs/2026-09-14_START-HERE.md`. Placement: `docs/runbooks/2026-09-14_TOPOLOGIES.md`.
> **Paper basis:** out-of-band tunnel + duplicate/latency signature - Zhukabayeva et al. 2025;
> duplicate-packet signature - Ramirez 2019 (`memory/thesis-citations.md`).

## Boards + hardware needed
| Role | Build (menu picks it) | Count |
|---|---|---|
| Root | `root_node/`, attack=wormhole (announces the phase) | 1 |
| Node A (exit / root-side) | `child_node/`, attack=wormhole, end=**A** | 1 |
| Node B (entry / leaf-side) | `child_node/`, attack=wormhole, end=**B** | 1 |

**Plus a UART jumper cable (3 wires) between Node A and Node B.** Minimum 3 boards.

## Timeline (fixed in firmware)
| Phase | Duration | Label | What happens |
|---|---|---|---|
| Stabilize | 60 s | (not logged) | mesh forms |
| Baseline | 300 s | `0` | Node B sends its probes straight to root (normal) |
| **Wormhole** | 180 s | **`2`** | Node B ALSO tunnels a copy to A over UART; A re-injects -> root gets it TWICE |
| Cooldown | 120 s | `0` | Node B stops tunnelling; single copy only |
| Terminate | instant | - | ready to export |

**Total ~11 minutes** from when the root finishes flashing.

## Step 1 - WIRE Node A <-> Node B (BEFORE powering on)
**Connection: [no laptop] this cable is only between the two attacker boards.** Use 3 jumper
wires, **crossed** (TX to the other board's RX), plus a shared ground:

| Node A pin | wire | Node B pin |
|---|---|---|
| GPIO 17 (TX) | ---> | GPIO 16 (RX) |
| GPIO 16 (RX) | <--- | GPIO 17 (TX) |
| GND | ---- | GND |

TX always crosses to RX (not straight-through). Do **not** connect this cable to your laptop.

> **WROVER modules with PSRAM:** GPIO16/17 are used internally by the PSRAM and are NOT safe.
> Edit `components\mesh_common\include\mesh_config.h` (`WORMHOLE_UART_TX_PIN` /
> `WORMHOLE_UART_RX_PIN`) to a free pair (e.g. 4 and 5), rebuild, and wire to those instead.

## Step 2 - TEST the wire first (30 seconds, saves an 11-minute wasted run)
A wrong wire makes the tunnel silently deliver nothing. Catch it with the loopback test:
```powershell
cd "C:\Users\Angelo Calpoporo\CLionProjects\NIS16-ESP32-Environment\uart_link_test"
idf.py set-target esp32                  # once
idf.py -p COM<nodeA> flash monitor        # press Ctrl+] at the banner
idf.py -p COM<nodeB> flash monitor        # WATCH this one
```
- `[LINK OK]` on the watched board -> wire is good, continue.
- `RX received=0` (stays 0) -> wire is broken; fix GND / the TX-RX crossing and retry.
Details: `uart_link_test\README.md`.

## Step 6 - Place boards + wait ~11 min
**Connection: [PWR] power only. KEEP the A<->B UART cable connected the ENTIRE run** (baseline and
cooldown too, not just the attack). A and B must be close enough for the cable; root can sit near
A. During the attack you'll see on B: `Tunnelled probe seq=... -> Node A via UART`, and on A:
`Re-injected probe src=... seq=...`. Don't touch anything during the run.

## Step 8 - Verify the SIGNATURE (the important part)
Files land in `tools\exports\wormhole\<topology>\<location>\` (root telem + arrivals, Node A telem,
Node B telem). Confirm the wormhole is real:
- **Root `arrivals.csv` - the DUPLICATE signature:** during `gt_label=2` rows, each of Node B's
  probes appears **TWICE** - two rows with the **same `src_mac` and same `seq_num`** but
  **different `latency_us`** (normal mesh copy vs slower tunnel copy) and different
  `timestamp_us`. During `gt_label=0` each `seq_num` appears **once**. That doubling + latency
  mismatch IS the wormhole signature.
- **Node B `telem.csv`:** `retry_count` (the "probes tunneled" counter) climbs only during
  `gt_label=2`; `tx_count` (forwarded to root normally) climbs the whole run.
- **Node A `telem.csv`:** `probes_count` (tunneled received) and `tx_count` (re-injected) both
  climb only during `gt_label=2`, ~0 elsewhere.
- **Paper-backed check (3-sigma):** duplicate count and latency-mismatch during label-2 windows
  are >3 sigma from the baseline phase (Zhukabayeva 2025 method). Run it:
  `python tools\verify_attack.py analysis\wormhole\<topology>\<location>\feature_table.csv --attack wormhole`
- If you saw `UART tunnel: bad magic` or `CRC mismatch` in a monitor -> wiring problem (loose
  jumper or wrong TX/RX crossing). Re-run Step 2.
- Automated: `python tools\validate_integrity.py`, `python tools\verify_topology.py`,
  `python tools\verify_attack.py` (above).
