# Runbook: BASELINE run (no attack) - v2026-09-14

> Normal mesh operation, **no attack**. Ground-truth label = `0` the whole run. Use this to
> collect benign data AND as a sanity check that your setup works. Hub: `docs/2026-09-14_START-HERE.md`.
> Board placement per topology: `docs/runbooks/2026-09-14_TOPOLOGIES.md`.

## Boards needed
| Role | Build target | Count |
|---|---|---|
| Root | `root_node/` | 1 |
| Victim | `child_node/` | 1 or more |

**Minimum 2 boards** (root + 1 victim). More victims = richer data; each just repeats the
victim steps on its own COM port. No cables between boards (baseline is wireless-only).

## Timeline (fixed in firmware - don't guess)
| Phase | Duration | Label | What happens |
|---|---|---|---|
| Stabilize | 60 s | (not logged) | mesh forms, root waits |
| Baseline | 300 s (5 min) | `0` | normal probes, telemetry logged |
| Cooldown | 120 s (2 min) | `0` | same as baseline, separate phase id |
| Terminate | instant | - | boards close CSV, ready to export |

**Total ~8 minutes**, timed from when the ROOT finishes flashing and reboots.

---

## Step 0 - Identify your boards (every session)
```powershell
.\menu.ps1   # -> "Identify a board"  (reads each board's MAC/node number)
```
Write board -> node -> MAC on your field log. COM = USB socket, not the board.

## Step 1 - Flash the VICTIM board(s) first
**Connection: [USB] victim board plugged into laptop.**
```powershell
.\menu.ps1
#  -> Run a board -> pick victim COM -> role: child -> topology: <your topology>
#     -> attack: none -> Flash: yes -> Wipe: yes -> Export: yes
```
Watch the monitor for:
```
=== VICTIM NODE STARTING ===
Probe generator task running at 1000 ms interval.
```
Press **Ctrl+]** to close the monitor (the board keeps running). Repeat for each victim.

*(Equivalent long command the menu runs: `.\run.ps1 -Port COM<v> -Role child -Topology <t> -Attack none -Wipe -Flash -Export`)*

## Step 2 - Flash the ROOT board LAST (with analysis)
**Connection: [USB] root board plugged into laptop.**
```powershell
.\menu.ps1
#  -> Run a board -> pick root COM -> role: root -> topology: <same topology>
#     -> attack: none -> Flash: yes -> Wipe: yes -> Export: yes -> Analyze: YES
```
Watch for:
```
=== ROOT NODE STARTING ===
[CTRL] Waiting 60 s for mesh to stabilise...
```
Press **Ctrl+]**. Root LAST + Analyze = yes means the full run (every victim + the root's
`arrivals.csv`) is present when the M6+M7+M8 pipeline auto-runs.

> **Do they run at the same time?** Yes, automatically. Each board runs the instant it boots;
> the root's phase broadcasts sync everyone's label over the mesh. Just flash victims first,
> then the root within ~1 minute so all boards join before baseline starts.

## Step 3 - Place boards + wait ~8 min
**Connection: [PWR] power only from here (USB data optional).** Don't touch/move/reset a board
during the run - it breaks the log. Placement for your topology: TOPOLOGIES runbook.

## Step 4 - Exit the monitors to export
When a board reaches `terminate`, press **Ctrl+]**. Because you chose Export (and Analyze on
the root), each board pulls its own CSV automatically; the root then runs the analysis.

---

## Step 5 - EXPORT (getting data off the boards)

### Way A - over USB (SPIFFS)
Already handled if you chose Export in the menu. To pull a board manually later:
```powershell
.\menu.ps1   # -> "Export a board only" -> pick COM, role, topology, attack: none
# equivalent: python tools\export_logs.py --port COM<x> --role <root|child> --topology <t> --location <loc> --attack none --repeat <n>
```
Root exports two files: `telem.csv` + `arrivals.csv`. One board at a time over USB.

### Way B - by SD card (fast, no per-board USB)
1. Power the boards **off**.
2. **Pop each microSD card out** and put it in your laptop's card reader.
3. `python tools\import_sdcard.py --card E:\ --repeat <n>` files the CSVs into
   `tools\exports\baseline\<topology>\<location>\` for you (see `docs/2026-09-14_SD-CARD.md`).
4. Re-insert cards before the next run.
This replaces the slow USB export step - the board is still what *created* the data.

---

## Step 6 - Verify (do this before trusting the run)
Files land in `tools\exports\baseline\<topology>\<location>\`:
- `<root>_..._telem.csv` and `<root>_..._arrivals.csv`
- one `<victim>_..._telem.csv` per victim board

Checks:
- Each `telem.csv` is non-empty, ~**4,800 rows** (480 s x 10 Hz sampling).
- The last column `gt_label` reads **`0` for the entire file** (baseline = no attack phase).
- Automated: `python tools\validate_integrity.py` (schema/labels/coverage) and
  `python tools\verify_topology.py` (parent/layer structure).
