# Runbook: VERIFY a run (paper-backed 3-sigma) - v2026-09-15

> No board touched. Confirms an attack run actually produced its expected cross-layer
> signature, by testing whether the attack-phase windows deviate more than k-sigma (default 3)
> from the BASELINE-phase distribution — the method of Zhukabayeva et al. (2025). Hub:
> `docs/2026-09-14_START-HERE.md`. Attack setup: `docs/runbooks/2026-09-14_BLACKHOLE.md` /
> `docs/runbooks/2026-09-14_WORMHOLE.md`.

## Prerequisite

An M7 `feature_table.csv` must already exist for the run you want to check:
```
analysis\<attack>\<topology>\<location>\feature_table.csv
```
It's produced by the analysis pipeline (M6+M7+M8) — either automatically, because you picked
`-Analyze` / `Analyze: YES` on the root during the run, or by running analysis manually
afterward. If the file isn't there yet, go run analysis first; there's nothing to verify.

## What it checks

| Attack | Primary signature (must clear 3-sigma) | Secondary (supporting) |
|---|---|---|
| Blackhole | `ForwardingRatio` down, `PDR` down | `ConsistencyScore`, `IngressEgressDelta`, `RetryRate` |
| Wormhole | `TunnelIntensity` up, `TunnelBytes` up, `TunnelLatency` up | `LatencyHopRatio` |

Each feature is tested only where it's defined (role-exclusive features are `NaN` off-role, e.g.
`ForwardingRatio` only exists on the attacker) — no node-role names are hardcoded. A feature
"PASSes" when the attack-phase mean sits more than `sigma` standard deviations from the
baseline-phase mean, in the expected direction.

## Step 1 - Run it from the menu
```powershell
.\menu.ps1
#  -> Verify a run -> which attack: auto-detect (or pick blackhole/wormhole)
#     -> topology -> location -> confirm the feature_table.csv path it shows you
```
*(Equivalent long command: `python tools\verify_attack.py analysis\<attack>\<topology>\<location>\feature_table.csv --attack <attack>`)*

## Step 2 - Or run it directly
```powershell
python tools\verify_attack.py analysis\blackhole\linear\home\feature_table.csv
python tools\verify_attack.py analysis\wormhole\tree\G402\feature_table.csv --attack wormhole --sigma 3
```
`--attack auto` (the default) detects blackhole/wormhole from the `Label` column itself, so you
only need `--attack` if the table somehow has ambiguous labels. `--sigma` overrides the 3-sigma
threshold if you need a looser/tighter check.

## Step 3 - Read the report
```
=== Verifying BLACKHOLE (Label 1) vs baseline (Label 0) ===
    baseline windows: 30   attack windows: 18
    3-sigma normal-vs-attack test (Zhukabayeva et al. 2025)

  feature             tier      baseline mu+-sd (n)      attack mean (n)      z  verdict
  ------------------------------------------------------------------------------
  ForwardingRatio     primary   0.981+-0.012 (30)         0.114 (18)      -72.3  PASS (v)
  PDR                 primary   0.976+-0.015 (30)         0.203 (18)      -51.6  PASS (v)
  ConsistencyScore    secondary 0.019+-0.012 (30)         0.886 (18)       72.1  PASS (^)
  ...

  VERDICT: BLACKHOLE CONFIRMED  (2/2 primary signatures exceed 3-sigma).
```
- **z** = how many baseline-sigmas the attack-phase mean moved, in the arrow's direction
  (`v` = expected to drop, `^` = expected to rise).
- **PASS** = that feature cleared the sigma threshold in the expected direction. **FAIL** = it
  didn't. **SKIP** = no attack-phase data for that feature on this node (role-exclusive, fine).
  **INCONCLUSIVE** = fewer than 2 baseline windows — need a longer/valid baseline phase.
- **VERDICT** looks only at **primary** features: `CONFIRMED` if at least one primary signature
  cleared 3-sigma, `NOT CONFIRMED` if none did, `INCONCLUSIVE` if no primary feature had usable
  data at all (wrong node roles present, or a table with no attack phase).
- Exit code: `0` if confirmed, `1` otherwise — safe to chain in a script
  (`&& echo ok || echo check the run`).

## Step 4 - If NOT CONFIRMED or INCONCLUSIVE
| Symptom | Likely cause |
|---|---|
| Blackhole: `ForwardingRatio`/`PDR` show `SKIP` everywhere | `BLACKHOLE_ATTACKER_MAC` wasn't set to the actual attacker's MAC — see BLACKHOLE runbook, box at the top |
| Wormhole: `Tunnel*` features all `SKIP` | UART wire between Node A/B is wrong — run the loopback test (WORMHOLE runbook Step 2b) |
| `INCONCLUSIVE - insufficient baseline windows` | run stopped early / baseline phase too short; re-run the full timeline |
| `This looks like a BASELINE-only table` | you pointed it at a baseline run's `feature_table.csv` — nothing to verify, that's expected |
| `NOT CONFIRMED` with real z-values just below threshold | attacker too far from victims / weak placement, or genuinely a borderline repeat — note it on the field log rather than discard it |
