## 🛠️ Three guards added after three separate failures

Each failure surfaced ~20 minutes downstream, when `features.py` finally refused the data.
All three now fail at the moment they happen.

### 1. `export_logs.py` — device sent the wrong file

`--role root` issues `EXPORT_LOGS` then `EXPORT_ARRIVALS`. On `star · wormhole · r1` the
second streamed **`telem.csv`** instead, so a good run was saved under an `_arrivals.csv`
name holding a copy of the telemetry. Both root files had the identical first data row.

`_check_expected_schema()` compares the stream's header against the file requested
(arrivals carry `src_mac`/`seq_num`, telemetry does not). On mismatch it **quarantines** the
capture as `....csv.rejected` — outside every downstream glob — and **skips `--delete`**, so
the board keeps the original.

> ⚠️ **Root cause not established.** Most likely a lost `END_OF_FILE` making the second
> capture re-read the first file, but that is unproven. The guard makes it detectable and
> non-destructive; it does not prevent the device from doing it again.

### 2. `trim_run.py` — stale files in `trimmed/`

That folder is written and never cleaned. The bad arrivals file was deleted from the raw
folder and re-pulled correctly, but its trimmed copy stayed — and every analysis tool reads
the **folder**, so `features.py` loaded both and died on the stale one, *after* the
re-export had already fixed the problem.

`_warn_on_stale_outputs()` lists anything in the output folder with no raw source. It warns
rather than deletes: derived data, but one command from being an only copy.

### 3. `trim_run.py` — duplicate captures

Exports are timestamped, so re-exporting or re-running a cell **adds** a file rather than
overwriting. Both copies then load and that board is counted twice. This one produced **no
error at all** — the root reached 264 windows against ~155 for every other node, and the
report looked plausible.

`_warn_on_duplicate_captures()` parses filenames into
`(role, label, topology, attack, repeat, kind)` and flags any key with more than one file.

**Audit:** all four existing capture folders — baseline·linear, blackhole·linear,
wormhole·linear, wormhole·star — are clean under both new checks.

### Also fixed

- `features.py` NaN hints were static text keyed on the column name, so a wormhole run
  printed `TunnelIntensity … [ATTACKER-ONLY: needs a wormhole run]` while that column held
  854 real values. Now reports what the data shows.
- `run_matrix.py` decoded the validator's output with the console codepage, printing every
  em-dash as mojibake. Needed **both** halves: `PYTHONIOENCODING=utf-8` on the child *and*
  `encoding="utf-8"` on the parent.
- `board_check.py` named boards by COM port (`-> COM26`) for a board sitting on COM20. Now
  reports **node numbers**, matching what `--label` uses.
- The runbooks' `MUST be 7` trimmed-file check now reads **7 per repeat** — a correct
  3-repeat run shows 21 and looked like a failure.
