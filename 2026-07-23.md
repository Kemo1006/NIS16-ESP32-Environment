## ❓ Q&A — The Null-Value Question (answered)

> **Your question:** *"Is it normal to have null values in some columns/rows in the EDA tables? Wormhole doesn't have a supposed value in PDR, right?"*

### ✅ Short answer: **Yes — NaN cells are normal, expected, and documented. Not a bug.**

### ⚠️ One correction to the framing
It's **not** that *"wormhole doesn't have PDR."* Wormhole runs **do** have PDR — it's populated for the **victim** rows (the probe senders). Verified directly against real data:

```
analysis/wormhole/linear_topology/feature_table.csv
  • 723 total rows
  • PDR is NaN on 268 rows  →  exactly the NON-victim rows
    (root + the two wormhole tunnel endpoints)
  • roles: victim=284, wormhole_b=171, wormhole_a=136, root=132
```

### 🧩 The three legitimate reasons a cell is NaN

| 🏷️ Type | Features affected | Why it's correct |
|---|---|---|
| 🎭 **Role-specific** | `PDR` (victims only) · `Tunnel*` (wormhole endpoints only) · `ForwardingRatio` / `IngressEgressDelta` / `ConsistencyScore` (blackhole attacker only) | A forwarding ratio is undefined for a node that doesn't relay; PDR is undefined for the root itself. **NaN ≠ zero.** |
| ⚔️ **Attack-specific** | `TunnelIntensity` · `TunnelBytes` | Only exist in wormhole runs — NaN in baseline & blackhole entirely. Thesis **Table 4.12**: *"null or zero for all other nodes and phases."* |
| 🔧 **Firmware-blocked** | `LatencyHopRatio` · `TunnelLatency` (+ currently the 3 forwarding features) | No RTT round-trip leg exists (probes are one-way), so latency can't be timed. **Flagged as NaN rather than faked.** |

### 🚨 One caveat to remember for the demo
`PDR = 0.0` vs `PDR = NaN` are **different meanings**:
- 🔴 `0.0` during an attack window = the **real blackhole signature** (root heard the node, but zero probes arrived).
- ⚪ `NaN` = the root **never heard that node at all** (coverage gap, wrong topology, CSV not pulled).

👉 Don't let these two get conflated in a plot — your code (`features.py`) already separates them correctly, keep it that way.
